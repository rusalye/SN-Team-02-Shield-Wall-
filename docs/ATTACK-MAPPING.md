## 1. Adversary behaviour to ATT&CK

| Attack in `attack_replay.py` | Technique | Tactic | Notes |
|---|---|---|---|
| SQL injection (login bypass, UNION, boolean blind) | **T1190** Exploit Public-Facing Application | Initial Access | Primary technique for all web exploits |
| Cross-site scripting (script tag, iframe URI, stored via feedback) | T1190 | Initial Access | |
| Path traversal (encoded `../`, null byte, query string) | T1190 | Initial Access | |
| OS command injection (`;cat`, `$()`, pipe to shell) | T1190, T1059 Command and Scripting Interpreter | Initial Access, Execution | T1059 is the intended post-exploit behaviour |
| NoSQL operator injection, B2B order RCE (virtual patches) | T1190 | Initial Access | |
| Scanner user agents (sqlmap, Nikto) | **T1595.002** Active Scanning: Vulnerability Scanning | Reconnaissance | |
| Honeypot probes (`/.env`, `/wp-login.php`, `/.git/config`) | T1595.003 Active Scanning: Wordlist Scanning | Reconnaissance | Decoy-path probing is typical wordlist behaviour |
| Login brute-force burst | **T1110** Brute Force | Credential Access | `T1110.001` Password Guessing is the specific sub-technique for a wordlist against one account |
| Request flood against general zone | T1498 Network Denial of Service | Impact | Only for rate-limit events outside the login path |

The three techniques named in the problem statement are **T1190, T1595.002 and T1110**; all appear in the generated alert summary and Navigator layer.
